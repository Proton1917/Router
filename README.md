# Router

Router 是一个通过外部 JSON 配置的 Rust 模型路由服务，提供 Tauri 桌面控制台、网页和命令行入口。你可以在界面中添加 API、选择模型、设置每个模型的标准与 Fast 目标，并创建自己的启动命令。

支持 Claude Code 使用的 Messages、Codex 使用的 Responses，以及 Chat Completions 接口。语音转写页面和 `spt` 命令支持音频转写、图片 OCR、任务进度、取消和结果导出。普通 API、模型、供应商和命令配置修改后直接生效；增加新的协议处理能力时需要修改 Rust。

当前桌面安装包适用于 **Apple Silicon、macOS 14 及以上**，项目采用 [MIT 许可证](LICENSE)。

## 安装与首次打开

### 准备需要的软件和账号

桌面包包含 Router、网页、SPT 引擎和配置示例。按需要准备以下内容：

| 用途 | 需要准备 |
| --- | --- |
| 调用 API | 自己的 API Key，以及服务商实际支持的接口和模型 ID；调用费用由相应服务商收取 |
| 启动 Claude Code | 已安装的官方 `claude` 客户端；本文的逐模型上下文设置使用 Claude Code 2.1.296 及以上版本 |
| 启动 Codex | 已安装的官方 `codex` 客户端；API 模式使用支持 Responses 的后端 |
| 运行客户端适配程序和 `spt` 命令 | Python 3，可通过 `brew install python` 安装 |
| 音频转写 | FFmpeg 和 FFprobe，可通过 `brew install ffmpeg` 一同安装；另需支持音频输入和结构化输出的模型 |
| 图片 OCR | 支持图片输入和结构化输出的模型 |
| Claude Code Mods | Python 的 `packaging` 依赖；Office 接入还需要 `lxml`、`jsonpointer`，详见 [客户端接入参考](docs/reference.md#客户端接入) |

### 安装桌面应用

使用 Homebrew：

```sh
brew install --cask Proton1917/tap/router
open -a Router
```

也可在 [v0.5.0 Release](https://github.com/Proton1917/Router/releases/tag/v0.5.0) 下载 `Router_0.5.0_aarch64.dmg`，打开后将 **Router.app** 拖入“应用程序”。

如需验证下载完整性，将安装包与同页的 `SHA256SUMS.txt` 放在同一目录，在该目录执行：

```sh
shasum -a 256 --ignore-missing -c SHA256SUMS.txt
```

确认输出 `Router_0.5.0_aarch64.dmg: OK`。校验文件也包含配套 SPT 源码包的记录，`--ignore-missing` 允许只下载桌面安装包。

当前应用采用 ad-hoc 签名，尚未经过 Apple 公证。首次打开受到 Gatekeeper 阻止时，确认下载来源后，在“系统设置 → 隐私与安全性”中允许打开。

### 创建本机配置

1. 打开 Router，展开“创建新配置”。
2. 确认以下四项。界面会自动填入当前用户的绝对路径；需要自定义时也填写绝对路径。
3. 保持“自动配置 Zsh 终端入口”选中，点击“安装并打开控制台”。
4. 重新打开终端，运行 `router status`，应看到 `gateway_online: true` 和当前配置文件路径。

| 设置 | 默认位置或值 | 用途 |
| --- | --- | --- |
| 配置目录 | `~/.config/router` | 保存 `router.json`、凭据、服务文件和任务数据，应位于 Git 工作区之外 |
| 终端入口目录 | `~/.local/bin` | 安装 `router` 包装命令，并通过 Zsh 初始化文件提供自定义命令 |
| 转发监听地址 | `127.0.0.1:8080` | Claude Code、Codex 等客户端发送模型请求的地址 |
| 控制台监听地址 | `127.0.0.1:8081` | 桌面窗口和网页使用的管理地址 |

已有 `router.json` 时，点击“选择已有配置文件…”。创建新配置会检查配置文件、安装资源、终端入口和端口冲突；提示已有文件时，可选择原配置或更换安装目录。

后续直接打开 Router 即可。执行 `router web` 会在浏览器中打开同一套控制台，默认使用 Safari。关闭窗口或退出桌面应用后，后台转发服务和已提交的转写任务继续运行。桌面窗口由 Tauri 提供，转发、管理 API 和网页由同一个 Rust 服务进程提供。

## 第一次配置 API 和启动命令

下面以创建一个名为 `mycc` 的 Claude Code API 命令为例。命令名称由你决定，之后也可以创建 `cc`、`ccor`、`cdx` 等不同入口。

主界面提供“启动命令”“服务与额度”“语音转写”。左下角“设置”包含服务参数、客户端接入和 Mods；高级设置提供共享模型配置、路由规则和启动方式。日常选择模型、设置 Fast 和上下文，统一在命令编辑窗口完成。

### 1. 配置 API 后端

进入“服务与额度”，编辑示例 `messages`，或点击“添加服务”：

1. 填写服务商的 **API 基础地址**。
2. 将“凭据来源”设为“独立凭据文件”，粘贴 API Key，点击“保存密钥文件”。输入框会清空，配置中保存凭据文件路径。
3. 按服务商要求填写“认证请求头模板”。保留 `{token}` 占位符，Router 会从凭据文件读取真实值。
4. 在“支持的接口协议”中勾选服务商实际支持的协议。Claude Code 使用 `messages`，Codex API 使用 `responses`，SPT 使用 `chat_completions`。
5. 点击“保存草稿 → 应用修改 → 确认应用”，让 Router 可以使用此后端读取模型目录。

示例配置的两个基础地址与认证模板如下。使用其他服务商时，按其文档调整：

| 服务 | API 基础地址 | 认证请求头模板 |
| --- | --- | --- |
| Anthropic Messages | `https://api.anthropic.com` | `{"x-api-key":"{token}"}` |
| OpenAI Responses | `https://api.openai.com` | `{"authorization":"Bearer {token}"}` |

Router 默认把接口路径附加到基础地址后，例如 `/v1/messages`。服务商提供的地址若已经包含 `/v1`，需核对最终路径并配置路径重写，见 [配置边界](docs/reference.md#配置边界)。

### 2. 创建终端命令并选择模型

1. 进入“启动命令”，点击“添加命令”。
2. 命令名称填写 `mycc`，启动方式选择“Claude Code API”。
3. 点击“添加模型”，将该条目的 API 后端设为 `messages`。右侧下拉框会读取该后端的完整模型目录，搜索并选择需要的模型；Router 自动创建模型绑定。
4. 在“默认启动模型”中选择这个模型。可以填写该条目自己的显示名称，并保留“在客户端菜单显示”。
5. 点击“保存草稿”。

“同步模型”立即刷新目录；“后台监控”按配置间隔检查新增、移除和元数据变化。目录接口不可用时保留上次结果，并提供“手动填写模型 ID”。账号的实际调用权限由上游处理请求时确认。目录字段、来源和缓存说明见 [模型目录同步](docs/model-catalogs.md)。

### 3. 应用并启动

1. 点击页面底部“应用修改”，阅读预览，再点击“确认应用”。“保存草稿”保留的是当前页面编辑，确认应用后才写入配置文件。
2. 在“启动命令”中确认 `mycc` 卡片列出了所选模型和 API 后端。
3. 打开新终端，输入 `mycc`。在 Claude Code 中使用 `/model` 查看模型菜单，再发送一条普通消息验证真实调用。

应用修改会自动同步 Zsh 命令，新增命令不需要逐个编辑 `.zshrc`。配置校验和“启动预览”检查配置与启动参数；真实调用还要求 API Key 有效、模型可用且账号额度充足。

## 使用 OAuth 登录服务商

在“服务与额度 → 编辑接入”中，将凭据来源设为 **OAuth · Router 独立登录**。服务商名称可以自由填写，无需选择内置服务商。

1. 填写服务商提供的 Client ID、令牌地址、权限范围，选择设备码授权或浏览器授权（PKCE）。设备码授权需要设备码地址；浏览器授权需要授权地址及已注册的本机回调地址。
2. 确认 OAuth 凭据文件位于 Git 工作区之外。不同账号使用不同文件；需要共享账号的多个后端使用同一文件和同一 Client ID、令牌地址。
3. 保存草稿、应用修改，再打开此后端，点击“登录并打开授权页”。在浏览器中完成授权；设备码方式会在 Router 中显示需要输入的代码。
4. Router 自动更新登录状态。可以在同一位置重新登录、刷新授权或退出本机账号。退出会删除这份本机凭据，同时影响共享该凭据的后端。

Router 直接完成授权和令牌刷新，不需要 OpenCode。访问令牌、刷新令牌和可选 Client Secret 存放在独立文件中，配置只保存引用；新凭据文件权限为 `0600`。授权服务需要支持标准 OAuth 2.0，并允许对应 Client ID 使用所选流程；仅填写服务商名称不能代替其授权参数。OAuth 登录权限与模型 API、订阅额度的可用范围由服务商决定。

设备码授权适用于远程使用 Router 的情况。PKCE 浏览器授权通过运行 Router 的电脑接收本机回调，回调地址格式为 `http://127.0.0.1:端口/路径`；只有服务商支持动态回调端口时才使用端口 `0`。公开参数示例见[OAuth 配置参考](docs/oauth.md)。

### 将 Router 作为其他客户端的提供商

Cherry Studio 等客户端可添加自定义提供商，Base URL 填写 Router 的转发地址，按后端支持的协议启用 Anthropic、OpenAI Chat Completions 或 Responses 端点。API Key 使用该 Router 客户端规则约定的本机标记；真实服务商凭据仍由 Router 管理。

`runtime.clients[].catalog_commands` 可以列出要共享的启动命令，例如 `["cc","ccor","cdx"]`。请求匹配这个客户端后，`GET /v1/models` 返回这些命令的可见模型，模型 ID 为 `命令/模型名称`；同一 ID 的推理请求自动使用对应模型配置及其标准/Fast 目标。修改命令中的模型绑定后，目录和路由随配置更新。具体配置见 [OAuth 与客户端接入参考](docs/oauth.md#共享模型目录)。

## 管理多个模型、Fast 和上下文

### 增加、切换或更换模型

在“启动命令 → 编辑命令与模型”中，点击“添加模型”，选择 API 后端，再从同步的目录中选择模型。替换已有条目时直接使用同一位置的模型下拉框。

命令编辑窗口中可以修改显示名称、调整顺序、显示或隐藏条目，并选择默认启动模型。展开“自定义标准与 Fast 目标”，配置供应商、服务等级及独立的 Fast 模型。替换范围默认是“仅此命令入口”；选择“共享配置的全部关联入口”时，窗口列出会受影响的命令、客户端及规则。Claude App 和 Office 在左下角“设置 → 客户端接入”中使用同一模型目录，客户端兼容标识继续保留。

点击“保存草稿 → 应用修改 → 确认应用”，然后重新启动该终端命令。Claude Code 可在 `/model` 中切换这些条目；Codex 使用其原生模型菜单。命令名称、模型菜单和路由都由配置决定。

### 标准与 Fast

每个模型有自己的“标准目标”和可选“Fast 目标”。Fast 目标可以使用不同的 API 模型、后端、供应商或上游服务等级；没有单独 Fast 目标时，Fast 沿用该模型的标准目标。

- **Claude Code**：在命令编辑窗口选择“Fast 控制方式”。默认“客户端 /fast”允许在会话内切换；也可以将该命令固定为标准或 Fast。命令的启动设置修改后，需要重新启动客户端。
- **Codex API**：可以设置“启动服务等级”。上游必须支持所配置的等级；实际速度、价格和限额由服务商决定。

Claude Code 原生 `/fast` 页面可能显示 Opus 的固定价格说明。第三方 API 的实际调用模型和费用以 Router 配置、上游响应和服务商账单为准。

### 每个模型的上下文预算

进入“启动命令 → 编辑命令与模型”，在各模型条目的“上下文预算（tokens）”中填写预算，保存、应用并重新启动命令。这个值控制 Claude Code 的自动压缩窗口，包含客户端预留空间；触发压缩时的输入 tokens 会低于所填数值。

后端提供并配置了上下文目录时，界面会读取当前模型及供应商的上限，标准和 Fast 共用预算时取两者较小值。点击“刷新模型上限”可重新读取。留空时沿用启动器基线，并受已识别上限限制。

首次安装的示例没有配置每家服务商的目录字段。在“服务与额度 → 编辑接入 → 模型上下文目录”中启用自动识别，并按服务商目录格式填写路径和字段。未公布数值的后端显示上限未知，填写预算也不能扩大上游的物理窗口。目录字段说明见 [上下文配置参考](docs/reference.md#cli-与本地管理界面)。

## Codex API 与独立账号登录

创建命令时选择“Codex · API／独立账号”启动方式，在编辑窗口设置默认启动模式和独立账号目录。

| 模式 | 凭据和计费来源 | 模型选择 |
| --- | --- | --- |
| API | Router 配置的后端凭据，按该服务商计费 | 使用命令绑定的模型；后端需原生支持 Responses |
| 独立账号 | 指定目录中的 ChatGPT 登录凭据，使用该账号订阅额度 | 使用 Codex 原生模型菜单 |

若命令命名为 `cdx`，可临时选择模式：

```sh
cdx --router-mode api
cdx --router-mode account login
cdx --router-mode account login status
cdx --router-mode account
```

独立账号模式的首次登录会打开官方登录流程，在浏览器中选择要使用的账号。该模式通过独立 `CODEX_HOME` 保存配置、凭据和会话。API 模式使用 Router 凭据，独立账号模式使用其自己的登录信息。两套模型设置分别保存，切换模式后重新启动客户端。

另一个“Codex 登录”启动方式直接使用客户端现有账号。模板和目录适配的具体字段见 [Codex 参考](docs/reference.md#codex)。

## 音频转写与图片识别

### 首次配置

1. 在“服务与额度”中配置支持 Chat Completions 的服务，勾选 `chat_completions`。音频转写还要求模型接受音频输入，OCR 要求接受图片输入，两者均需要结构化输出能力。
2. 在“设置 → 高级设置 → 共享模型配置”中创建一个固定 API 模型的配置。没有可关联的普通客户端命令时，在“创建可调用名称”填写一个唯一名称，例如 `transcription-main`。
3. 打开“语音转写 → 转写设置”，点击“添加模型”，选择上述模型配置，并设置默认模型。
4. 填写“响应模型标识”。它用于核对上游实际返回的模型，可填写稳定的版本前缀；应使用 API 响应中的 `model` 名称，不使用菜单显示名称。
5. 展开“引擎、依赖与任务目录”，核对以下路径，点击“保存草稿”，再在页面底部应用修改。

| 设置 | 桌面首次安装的默认值 |
| --- | --- |
| SPT 可执行文件 | `application/bin/spt-core` |
| SPT 引擎配置文件 | `application/examples/spt-engine.toml` |
| FFmpeg 可执行文件 | `/opt/homebrew/bin/ffmpeg` |
| FFprobe 可执行文件 | `/opt/homebrew/bin/ffprobe` |
| 任务存储目录 | `transcriptions` |

相对路径以 `router.json` 所在目录为基准。安装 FFmpeg 后，可用 `command -v ffmpeg` 和 `command -v ffprobe` 查找实际路径，再填入设置。桌面包已包含 SPT；仅命令行安装时需要另行部署引擎，见 [部署参考](docs/reference.md#安装命令行与网页)。

### 提交和导出

在“语音转写”页面选择处理类型、模型和文字处理方式，拖入文件后点击“开始处理”。音频支持 M4A、MP3、WAV、FLAC 等格式，图片支持 PNG、JPEG、WebP。任务记录展示处理阶段和音频时长进度，完成后可预览正文、导出 Markdown 或结构化 JSON。

首次创建配置已经提供 `spt` 启动命令，它与网页共享模型和处理参数：

```sh
spt "会议录音.m4a"
spt --raw "会议录音.m4a"
spt ocr "扫描图片.png"
spt models
spt --model
spt --model 'model-1'
spt config
```

`spt models` 或 `spt --model` 列出可选标识；用实际列出的标识替换示例中的 `model-1`。`spt --model <标识>` 会持久保存默认模型，网页中的默认选择也随之更新。`spt config` 打印当前转写设置。

终端处理完成后，在原文件旁写入同名 `.md`；`--raw` 写入 `.raw.md`，OCR 写入 `.ocr.md`。已有文件时停止写入，添加 `--force` 可在任务成功后替换已有文字稿。Ctrl+C 请求取消后台任务。网页上传产生的结果通过页面导出，终端命令提交的任务同样显示在任务记录中。

### 资源、数据和后台运行

转写设置可以调整上传大小、总存储、单任务临时空间、并发数、任务数量、保留天数、分段秒数、输出 tokens 和重试次数。初始设置为单文件 256 MiB、总空间 3 GiB、并发 1、最多 64 个任务、结果保留 30 天。

每个任务使用独立 SPT 工作进程，并固定创建时的模型路由和处理参数。后续修改配置作用于新任务。关闭控制台后任务继续运行；停止或重启后台 Router 会中断任务，启动后将未完成记录标为中断，需要重新提交。

上传文件和临时音频在任务成功、失败或受控取消后清理。结果按保留天数清理，也可在页面删除。语音或图片内容会发送给所选上游模型服务；结果、任务记录和已导出的文件分别保存在本机。

## 常用命令与配置生效时间

```sh
router web                       # 打开浏览器控制台
router status                    # 显示服务状态、地址和配置路径
router commands list             # 列出已配置命令
router run mycc --dry-run         # 查看启动参数，不发送模型请求
router config check              # 校验配置和路由用例
router web --restart             # 重启后台服务并打开控制台
```

| 修改内容 | 生效方式 |
| --- | --- |
| API 地址、凭据文件内容、模型路由和供应商 | 应用后，后续请求读取新配置 |
| 命令名称和启用状态 | 应用后自动同步终端入口；首次安装需重新打开终端 |
| 客户端模型菜单、上下文预算、启动参数和登录模式 | 应用后重新启动相应客户端命令 |
| 转写模型和处理参数 | 新任务使用新配置，正在执行的任务保留原设置 |
| 监听地址、HTTP 超时、正文资源设置或转写任务目录 | 需要重启后台服务；重启前先完成或取消正在执行的转写任务 |

页面通过配置变化事件自动更新。有未保存草稿时会保留编辑并提示新配置。桌面窗口在支持的 macOS 版本使用原生 Liquid Glass；窗口尺寸和材质可在配置目录的 `desktop.json` 调整，重新打开控制台后读取。

## 升级已有安装

Homebrew 更新桌面应用：

```sh
brew update
brew upgrade --cask router
```

手动安装用户可下载新版 DMG 并替换 Router.app。**后台程序、网页和脚本是首次安装时复制到配置目录的，升级 Router.app 后，还需更新这些已部署资源。**

1. 运行 `router status` 确认当前配置文件，查看其 `management.assets_directory` 及服务使用的可执行文件路径。
2. 完成或取消当前转写任务，退出正在使用待更新启动脚本的客户端。
3. 打开新版 `Router.app` 的“显示包内容”，进入 `Contents/Resources/resources/`。
4. 按下表将新版资源复制到当前配置实际使用的位置。先将新版 `router` 复制为同目录临时文件并保留可执行权限，再重命名替换正式文件，避免直接覆盖运行中的程序。
5. 运行 `router web --restart`，再重新启动需要更新菜单或启动参数的客户端。

| 包内资源 | 桌面默认部署位置，相对于配置目录 |
| --- | --- |
| `router` | `application/bin/router` |
| `spt-core` | `application/bin/spt-core` |
| `web/` | `application/web/` |
| `scripts/` | `application/scripts/` |
| `examples/spt-engine.toml` | `application/examples/spt-engine.toml`，更新时保留自己的处理参数 |
| `LICENSE`、`THIRD_PARTY_NOTICES.txt`、`SPT-LICENSE`、`spt-licenses/` | `application/` 下对应文件或目录 |

已有部署可能使用其他路径，以实际配置为准。升级资源时保留 `router.json`、`credentials/`、独立登录目录、客户端自定义设置和已有结果。新增功能需要的配置通过控制台或配置参考导入；选择已有配置会沿用其原有启动方式和命令。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 终端找不到 `router` 或新命令 | 首次安装后重新打开 Zsh；在控制台点击“同步终端入口”。自定义终端配置时，加载 `router commands install` 返回的 `shell_init` 文件 |
| 页面提示未授权，或直接输入网页地址打不开配置 | 使用桌面应用或 `router web` 打开，它们会提供本机管理令牌 |
| 点击保存后客户端菜单没有变化 | 确认已经完成“应用修改 → 确认应用”，然后重新启动客户端 |
| 新模型提示需要关联入口 | 新增模型时选择现有命令，或填写“创建可调用名称” |
| 启动程序找不到 `claude`、`codex` 或 Python | 先安装相应程序，在“启动方式”中填写其实际路径；Codex 模板通过参数数组指定 `codex` 程序 |
| 模型目录 404、获取失败或缺少配置模型 | 核对目录 API 的独立地址、认证方式、字段和模型 ID。目录和推理接口可能使用不同路径，见 [目录参考](docs/reference.md#cli-与本地管理界面) |
| 401、403、429 或 503 | 查看具体上游错误和 `logs/gateway.log`，核对凭据、模型权限、额度和供应商状态。Fast 与重试仍受上游限额约束 |
| 提示最大上下文不足 | 依据当前供应商端点上限调整上下文预算和输出 tokens；模型名称相同的不同端点可能具有不同限制 |
| 转写失败、依赖缺失或响应模型不符 | 检查引擎与 FFmpeg 路径、模型音频／图片能力及“响应模型标识”；任务记录会保留具体错误 |
| Word、Excel 中没有入口或同步失败 | 首先完成客户端安装、清单和 HTTPS 网关配置；macOS 容器访问受限时，按错误信息为实际后台程序配置访问权限，详见 [客户端接入参考](docs/reference.md#客户端接入) |

Claude App 和 Office 接入是可选配置。首次安装示例需要用户提供这些客户端的实际目录、网关和模型入口；具体方式见 [客户端接入](docs/reference.md#客户端接入)。Claude Code 插件组合见 [Mods 管理](docs/reference.md#mods-管理)。

## 本机文件与凭据

桌面默认配置目录为 `~/.config/router`：

| 路径 | 内容 |
| --- | --- |
| `router.json` | API、模型、路由、命令及管理配置 |
| `credentials/` | API 凭据文件；Codex 独立账号目录以命令设置为准 |
| `control-token` | 本机管理令牌 |
| `application/` | 运行程序、网页、适配脚本和许可材料 |
| `commands.zsh`、`commands.init.zsh` | 自动生成的终端入口及其初始化文件 |
| `service.plist` | macOS 后台服务定义 |
| `desktop.json` | 桌面窗口尺寸和材质 |
| `logs/` | 运行日志，默认每 5 分钟维护，单文件约 4 MiB、总量约 16 MiB 的清理阈值 |
| `transcriptions/` | 转写任务记录和结果，位置及保留时间可在界面调整 |

API Key 写入独立凭据文件，配置保存引用；标准 OAuth 登录和自动刷新由 Router 管理，专用协议也可通过外部凭据命令或本机适配服务接入。独立凭据目录须位于 Git 工作区之外，密钥文件权限为 `0600`。仓库只分发源码、配置示例和文档，本机配置、凭据、日志、任务数据及运行二进制由忽略规则排除。
